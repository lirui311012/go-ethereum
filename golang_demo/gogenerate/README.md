# go generate

`//go:generate` 是一行注释。编译、测试、运行都不会执行它。`go generate` 是另外一条命令，它把这行后面的程序跑起来，那个程序再写出新的 `.go` 文件。下次编译时，新文件和手写的文件一起编进去。

本目录用一个小生成器把这件事走一遍。生成出来的 `EncodeGen` 和手写的 `EncodeReflect` 对同一个 `Account` 写出同样的字节。差别在于：前者的字段访问写死在源码里，后者每次调用都用 `reflect` 看字段。`rlp/rlpgen` 和 `core/types/gen_header_rlp.go` 就是这件事的正式版本。

## 编译器看到什么

`account.go` 里有这一行：

```go
//go:generate go run ./gen -type Account -out gen_account.go
```

它必须从行首开始写，`//` 和 `go:generate` 之间没有空格。对编译器来说，整行都是注释，和写 `// TODO` 一样，会被丢掉。所以：

- `go build`、`go run`、`go test` 不会启动 `./gen`
- 改了 `Account` 的字段之后，`gen_account.go` 不会自己更新

`go generate` 不理解 Go 的类型。它把每个 `.go` 文件当文本扫一遍，找到这种行，按空格拆成命令和参数，在这个文件所在的目录里执行。这里拆出来的就是：

```text
go run ./gen -type Account -out gen_account.go
```

执行前它还会放上几个环境变量，例如 `GOFILE`（当前文件名）、`GOLINE`（行号）、`GOPACKAGE`（包名）。本示例和 `rlpgen` 都没读这些变量，类型名和输出文件已经写在参数里。

命令自己的输出会原样打出来。成功时 `go generate` 默认不再多说什么。加上 `-n` 只打印将要执行的命令，不真正跑；加上 `-x` 会在执行时把命令也打出来。

## 生成器做了什么

`gen/main.go` 是一个普通的 `package main`。它做三件事：

1. 用标准库 `go/parser` 解析当前目录的源码，得到语法树。这一步没有把包编译，也没有用 `reflect`。`reflect` 要等程序跑起来、值装进接口之后才能看类型；生成发生在那之前，眼前只有源码文本。
2. 找到名为 `Account` 的结构体，按源码顺序列出导出字段。`note` 未导出，打印一行后跳过。
3. 按字段类型拼出一个方法，用 `go/format` 格式化，写到 `gen_account.go`。

它只认识三种写法：`uint64`、`string`、`[]byte`。因为这里看的是文本。`uint64` 这两个字写在源码里，生成器就知道该调用 `w.Uint64`。

`Header` 的字段是 `common.Hash`、`*big.Int` 这种别的包里的具名类型。只看 `common.Hash` 这几个字，不知道它底层是 `[32]byte`。`rlp/rlpgen` 因此多做了一步：用 `golang.org/x/tools/go/packages` 把包加载成编译器的类型信息（`go/types`），再判断一个类型是不是实现了 `rlp.Encoder`、tag 该怎么处理。加载和分派在 `rlp/rlpgen/main.go` 的 `process` 和 `gen.go` 的 `makeOp`。

生成文件的第一行是 `Code generated by gendemo. DO NOT EDIT.`。这个文件可以读，用来理解生成结果；改它会被下一次 `go generate` 覆盖。

## 为什么还要留一份反射实现

`EncodeReflect` 在每次调用里做这些事：`reflect.ValueOf`，解开指针，`NumField`，跳过未导出字段，按 `Kind` 选择 `Uint64` / `String` / `Bytes`。`rlp/encode.go` 的 `makeStructWriter` 是同一类循环，只是它还会处理 tag、空指针和嵌套类型。

`EncodeGen` 的函数体是：

```go
func (obj *Account) EncodeGen(w *Writer) {
	w.Uint64(obj.Nonce)
	w.Uint64(obj.Balance)
	w.String(obj.Name)
	w.Bytes(obj.Code)
}
```

调用它的时候，字段有哪些、每个字段用哪个方法，已经是普通的 Go 代码。编译器按普通方法来编译。

两边规则对齐（导出字段、源码顺序、同一种字节布局），所以输出的十六进制相同。`note` 的值 `"hidden"` 不会出现在任何一边。

字节布局是为了对照而造的，不是 RLP：`uint64` 固定 8 字节大端；`string` 和 `[]byte` 先写 4 字节长度，再写内容。

| 字段 | 值 | 字节 |
|---|---|---|
| `Nonce` | `1` | `0000000000000001` |
| `Balance` | `100` | `0000000000000064` |
| `Name` | `"ab"` | `00000002` `6162` |
| `Code` | `{0x60, 0x00}` | `00000002` `6000` |

## 区别，以及会不会二选一

两条路写的是同一份字节：只要导出字段、源码顺序和上面的布局不变，结果就一样。`main.go` 对同一个 `Account` 各调一次，是为了把两串十六进制摆在一起看。演示程序两边都跑；真正拿一个值去编码时，一个类型只用其中一条。

| | `EncodeGen` | `EncodeReflect` |
|---|---|---|
| 字段在什么时候定下来 | `go generate` 把 `gen_account.go` 写出来的时候 | 每次调用 `EncodeReflect` 的时候 |
| 调用时在做什么 | 执行已经写好的 `w.Uint64(obj.Nonce)` 这类语句 | 用 `reflect` 看字段和种类，再决定调用哪个 `Writer` 方法 |
| 改了 `Account` 的字段 | 要重新 `go generate`，否则方法里还是旧字段 | 下一次调用按新的结构体走 |
| 写在哪 | `gen_account.go` | `encode_reflect.go` |

仓库里也是按类型二选一，不是整个项目只用一种。`rlp.Encode` 不让调用方指定走哪边。`makeWriter` 第一次见到某个具体类型时选定一份 writer，放进 `typecache`，之后这个类型一直用那一份：

- 类型有 `EncodeRLP`（`rlpgen` 生成的，或人写的）：之后编码调用这个方法。`Header` 用 `gen_header_rlp.go`，`makeStructWriter` 那套逐字段反射不会再对它跑。
- 类型没有 `EncodeRLP`：writer 就是 `makeStructWriter`。它对应本示例的 `EncodeReflect`。

同一个类型不会两套都写一遍。有生成方法的类型只走生成的方法；没生成的类型只走反射。`rlp.Encode` 入口仍有一次 `reflect.ValueOf`，用来查出该用哪一份 writer。省掉的是每个字段上的反射。

## 类型缓存

`typecache.go` 把上面的选择做成可运行的代码。`EncodeCached` 先按具体类型取一份 `typeWriter`，再交给它写。这份函数第一次见到该类型时由 `makeWriter` 造出来，放进 map，之后同一个类型只打印 `cache hit`。

`Account` 有 `EncodeGen`。缓存见到 `*Account` 时解开指针，发现 `*Account` 实现了 `Encoder`，于是留下的函数只做 `EncodeGen(w)`。字段列表不再看，`note` 也不会在这一步被提到。`note` 的跳过发生在 `go generate`。

`Transfer` 没有这个方法。缓存改为编译反射 writer：当时记下 `Amount`、`Note` 的下标，调用时按下标取值。这和 `EncodeReflect` 用的是同一套 `writeValue`，但 `EncodeReflect` 每次调用都重新 `NumField`。第二次编码 `Transfer` 不再打印字段。

查找这里用一把 `sync.Mutex`。`rlp/typecache.go` 的读路径不加锁：已有的表用 `atomic.Value` 整张发布，只有生成新类型时才加锁。

## 什么场景用反射，什么场景用生成

反射是默认路径，生成代码是给少数热点类型用的。一个类型只走其中一条：有 `EncodeRLP` 就调用它，没有就用反射。

反射适合类型在写代码时还定不下来的地方。`rlp.Encode`、`encoding/json`、RPC 注册的参数都是 `interface{}`，调用方传入什么结构体，要等运行时才知道。这种类型数量开放，不会为每一个都提交一份生成文件。`Transfer` 就是这种：没有 `EncodeGen`，类型缓存第一次见到它时记下字段下标，之后按下标用 `reflect.Value` 取值。类型缓存省掉的是「再看一遍有哪些字段」，每次编码仍然要经过反射。

生成适合类型已经确定、而且会反复编码的地方。区块头在同步和传播时不断被编码，字段也固定。`rlpgen` 在 `go generate` 时把 `Header` 的字段写成 `w.WriteBytes(obj.ParentHash[:])` 这种普通语句，编译器按普通方法编译。调用时不再逐字段反射。结构体或 `rlp` tag 改了，要重新生成并提交 `gen_header_rlp.go`；`go build` 不会自己做这件事。

仓库里的分界就是这条。入口一律先 `reflect.ValueOf`，只为查出该用哪份 writer。`Header`、`Log`、`Withdrawal` 这类热点类型带了 `//go:generate`，缓存选定它们的 `EncodeRLP`。其余类型没有这方法，就留在 `makeStructWriter` 的反射路径上。

## geth 为什么要生成

手写 `EncodeRLP` 可以，区块头字段多，还要和反射那套 tag 规则保持相同的字节。生成器把同一套规则打印成源码，避免两份实现慢慢写岔。改了 `Header` 的字段或 tag，要重新生成 `gen_header_rlp.go`。`go run ./build/ci.go check_generate` 会再跑一遍 `go generate ./...`，生成结果和仓库里的文件不一致就失败。

## 运行

在本目录执行：

```sh
go generate -n
go generate
go run .
```

`go generate -n` 只打印命令。`go generate` 会真正重写 `gen_account.go`。

```text
go run ./gen -type Account -out gen_account.go
account.go
encode_reflect.go
main.go
typecache.go
writer.go
gendemo: 跳过未导出字段 note
gendemo: 已写入 gen_account.go，字段 Nonce uint64，Balance uint64，Name string，Code []byte
EncodeGen     00000000000000010000000000000064000000026162000000026000
EncodeReflect 00000000000000010000000000000064000000026162000000026000
字节相同       true

cache miss *main.Account
  *main.Account 是指针，继续看 main.Account
  main.Account 有 EncodeGen，之后只调用这个方法
cache hit *main.Account
Account 经缓存 00000000000000010000000000000064000000026162000000026000
与 EncodeGen 相同 true

cache miss *main.Transfer
  *main.Transfer 是指针，继续看 main.Transfer
  main.Transfer 没有 EncodeGen，按字段编译反射 writer
  字段 Amount uint64
  字段 Note string
cache hit *main.Transfer
Transfer 经缓存 000000000000000700000002676f
两次字节相同     true
```

删掉 `gen_account.go` 再 `go run .`，编译会报 `EncodeGen` 未定义。再执行 `go generate`，文件回来，`go run .` 恢复。这就是「生成文件要提交进仓库」的原因：编译时期望它已经在，编译过程不会把它造出来。

## 和仓库里的对应关系

| 本示例 | go-ethereum |
|---|---|
| `account.go` 的 `//go:generate` | `core/types/block.go` 的 `go run ../../rlp/rlpgen -type Header -out gen_header_rlp.go` |
| `gen/main.go` 读语法树、写方法 | `rlp/rlpgen` 读类型信息、写 `EncodeRLP` |
| `gen_account.go` | `core/types/gen_header_rlp.go` |
| `EncodeReflect` | 每次调用都走反射的那一版，用来和 `EncodeGen` 对照字节 |
| `typecache.go` | `rlp/typecache.go`。按类型选定 writer，之后复用 |
| `Transfer` | 没有 `EncodeRLP` 的类型，缓存里留下 `makeStructWriter` |
| 默认只跑生成器这一次 | 默认只生成 `EncodeRLP`；`bal_encoding.go` 加了 `-decoder` 才生成 `DecodeRLP` |
